# E12-X1.10 — Continuous Productive Surface

## Decisione

E12-X1.9 ha dimostrato che:

- Q0 può essere saturato già nel Day 1;
- Q1 può essere acquistato molto presto;
- Q2 può essere acquistato entro la prima parte dell'episodio;
- 8 Cow sono raggiungibili;
- source/submission equivalence è stabile.

X1.9 ha però fallito sul problema centrale del midgame:

> **la superficie produttiva non viene mantenuta continuamente.**

Dopo gli harvest molti tile escono dal working set, non vengono replanted, gli Hands restano idle e la farm compra nuova terra senza sfruttare quella già posseduta.

X1.10 deve correggere esclusivamente questo problema architetturale e i problemi direttamente collegati:

1. continuous productive surface;
2. replant immediato;
3. utilizzo completo di Q0+Q1 entro radius 5;
4. Q2 acquistato solo dopo stabilizzazione;
5. Q2 convertito immediatamente dopo l'acquisto;
6. crop mix economicamente migliore;
7. livestock core B corretto;
8. livestock non deve sottrarre capacità alla macchina crop.

---

# 1. Principio architetturale

La regola fondamentale X1.10 è:

```text
OWNED + WITHIN ACTIVE RADIUS + USABLE
=
MUST REMAIN PRODUCTIVE
```

Un tile produttivo non deve uscire dalla superficie attiva semplicemente perché:

- è stato raccolto;
- è temporaneamente empty;
- cambia crop;
- viene rivalutato il working set;
- il crop precedente ha completato il proprio ciclo.

Il ciclo corretto è:

```text
PLANT
→ WATER / MAINTAIN
→ HARVEST
→ REPLANT
→ WATER / MAINTAIN
→ HARVEST
→ ...
```

Non:

```text
PLANT
→ HARVEST
→ EMPTY
→ working-set exclusion
```

---

# 2. Definizione di Continuous Productive Surface

Definisci esplicitamente una nozione di:

```text
active_productive_surface
```

che includa i tile posseduti, utilizzabili e appartenenti al working radius corrente.

Per ogni tile appartenente alla superficie produttiva attiva deve esistere sempre uno stato operativo fra:

```text
PASTURE
PLANTED
GROWING
HARVEST_READY
HARVESTED_PENDING_REPLANT
REPLANTED
```

Lo stato:

```text
EMPTY
```

è ammesso esclusivamente per il numero minimo di turni tecnicamente necessario fra harvest e replant.

# 5. Acquisto Q1

Q1 può essere acquistato presto come in X1.9.

Dopo l'acquisto di Q1 cambia immediatamente il target operativo.

Il working set diventa:

```text
tutti i tile owned
dentro radius <= 5
esclusi livestock cores
```

Q0 e Q1 devono quindi essere trattati come una singola superficie produttiva continua.

---

# 6. Saturazione Q0 + Q1

Dopo Q1:

```text
Q0 + Q1 within radius 5
```

devono convergere alla saturazione produttiva.

Non usare più soglie tipo:

```text
70%
75%
```

come definizione di successo.

L'obiettivo è:

```text
100% dei tile usable owned entro radius 5
```

salvo tile temporaneamente:

- in transizione harvest/replant;
- occupati da worker;
- bloccati da una condizione meccanica reale.

---

# 7. Continuous maintenance gate prima di Q2

Q2 NON può essere comprato solo perché esiste cash sufficiente.

Prima di Q2 deve essere dimostrata la stabilità di Q0+Q1.

Definisci:

```text
radius5_productive_utilization
```

come:

```text
productive usable owned tiles within radius5
/
total usable owned tiles within radius5
```

Prima di comprare Q2 richiedi:

```text
radius5_productive_utilization >= 0.95
```

per almeno:

```text
2 consecutive full days
```

Idealmente:

```text
1.00
```

tolti i tile in transizione intra-turno.

Inoltre:

```text
harvested_not_replanted <= 2 per day
```

per almeno 2 giorni consecutivi.

Q2 deve essere considerato:

```text
LOCKED FOR EXPANSION
```

finché questi gate non sono soddisfatti.

---

# 8. Harvest -> replant invariant

Questa è la verifica principale X1.10.

Ogni crop non-ongoing raccolto deve diventare:

```text
REPLANT_PENDING
```

immediatamente.

Priorità azioni:

```text
1. HARVEST_READY
2. REPLANT_PENDING
3. WATER_AT_RISK
4. WEED_RECOVERY
5. NEW_EXPANSION
```

Il replant deve avere precedenza sulla creazione di nuovi tile produttivi.

Acceptance:

```text
same-day replant preferito
next-day replant massimo
```

Target diagnostico:

```text
harvested_not_replanted < 5/day
```

Acceptance X1.10 più severa:

```text
<= 2/day
```

durante lo steady state Q0+Q1.

---

# 9. Persistent working set

Il working set non deve essere ricostruito esclusivamente dai tile crop attualmente esistenti.

Deve derivare da:

```text
owned geometry
+
active radius
+
reserved livestock tiles
```

Quindi un tile appena harvested resta membro del working set.

Verifica ed elimina qualunque logica equivalente a:

```text
if tile is empty:
    exclude_from_working_set
```

quando il tile appartiene alla superficie produttiva desiderata.

---

# 10. Workforce assignment

L'audit ha mostrato molti worker-turn idle pur con terra disponibile.

X1.10 deve assegnare gli Hands alla superficie target, non alla superficie già attiva.

Formula concettuale:

```text
desired productive surface
→ required maintenance actions
→ required workers
→ HIRE
```

Non:

```text
existing crop count
→ worker count
```

La domanda giornaliera deve essere:

> quanti worker-turn servono per mantenere tutti i tile target produttivi oggi?

Calcola almeno:

```text
harvest actions
replant actions
water actions
weed actions
movement overhead
```

e deriva il target Hands.

---

# 11. Idle workforce invariant

Se esistono contemporaneamente:

```text
idle owned usable tile within radius
+
available seed
+
idle Hand
```

l'Hand non deve fare PASS.

Lo stesso vale se esiste:

```text
harvested_pending_replant
```

Acceptance:

```text
idle worker-turns while actionable productive work exists
≈ 0
```

Registra comunque eventuali eccezioni meccaniche.

---

# 12. Radius logic

Mantieni:

```text
radius <= 5
```

come working radius iniziale.

Il radius deve essere calcolato rispetto al centro/core e applicato alla geometria owned.

Non deve dipendere dal numero attuale di crop.

Dopo Q1:

```text
Q0 + Q1 radius5 full
```

prima di Q2.

Dopo Q2:

```text
Q0 + Q1 + Q2 radius5
```

diventa il nuovo target.

---

# 13. Q2 purchase

Q2 viene acquistato solo dopo il Continuous Productive Surface gate.

Condizioni minime:

```text
Q0+Q1 radius5 utilization >= 0.95
for >= 2 days

harvested_not_replanted <= 2/day
for >= 2 days

cash >= real Q2 cost + operating reserve
```

Non usare un day threshold fisso.

Non usare solo cash.

---

# 14. Q2 activation

Subito dopo `BUY_LAND Q2`:

```text
Q2 conversion starts same day
```

Priorità geometrica:

```text
nearest tile to center first
```

Target:

```text
>= 12 productive Q2 tiles within 3 days
```

ma il vero obiettivo è arrivare alla saturazione di tutti i tile Q2 owned entro radius 5.

---

# 15. Q2 maintenance

Una volta entrato nel working set:

```text
Q2 tile harvested
```

deve seguire lo stesso invariant:

```text
HARVEST
→ REPLANT
```

Non deve esistere una logica differente per i quadranti successivi.

---

# 16. Crop mix

X1.9 utilizza troppo Wheat/Carrot e nessun Tomato/Strawberry.

X1.10 deve distinguere:

```text
SERVICE CROPS
CASH CROPS
```

## Wheat

Wheat serve principalmente a:

```text
feed requirement
+
safety buffer
```

Definisci un target dinamico:

```text
required_feed_buffer =
expected near-term animal consumption
+
safety reserve
```

Non piantare Wheat oltre questo fabbisogno senza ragione economica.

---

# 17. Cash crop allocation

Una volta soddisfatto Wheat buffer, assegna il resto della superficie a crop economicamente migliori.

Non hardcodare la scelta solo sul market price istantaneo.

Valuta almeno:

```text
yield
growth duration
ongoing/non-ongoing
market value
worker burden
replant frequency
```

Costruisci una metrica semplice:

```text
expected revenue per tile-day
```

Usala per ordinare le cash crops.

Devono poter comparire anche:

```text
Tomato
Strawberry
Melon
```

se economicamente superiori nelle condizioni correnti.

---

# 18. Continuous crop value

La scelta crop non deve rompere la continuità.

Se una coltura ha alto valore ma impone un ciclo operativo non mantenibile dalla workforce, riducine l'allocazione.

Priorità:

```text
continuous productive surface
prima di
local maximum crop price
```
