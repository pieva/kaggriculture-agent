# E12-X1.9 — Growth-First Concurrent Architecture

Implementa la nuova architettura **E12-X1.9** partendo dalla baseline X1.8 validata sul piano livestock ma fallita sul piano della velocità di crescita.

## Decisione architetturale

X1.8 ha dimostrato che il 2×2 livestock core può essere mantenuto in modo stabile.

L'audit Day-1 ha però dimostrato che la serializzazione:

```text
core
→ cow
→ feed
→ crop
```

è il principale errore.

X1.9 deve sostituirla con una strategia concorrente:

```text
livestock core
+
crop mass
+
workforce
+
land expansion
```

che procedono in parallelo.

---

# 1. Obiettivo primario Day 1

Q0 contiene 25 tile.

Il 2×2 livestock core occupa 4 tile.

Restano:

```text
21 tile crop
```

## Acceptance criterion obbligatorio

Alla fine del Day 1:

```text
4 livestock-core pasture
+
21 crop tile esterni
```

Target:

```text
crop_planted = 21
crop_watered = 21
```

Non usare più obiettivi vaghi tipo:

```text
>= 12
>= 16
significant crop mass
```

La verifica deve essere binaria:

```text
Q0 external crop saturation = PASS / FAIL
```

Se per una ragione meccanica reale 21/21 non è ottenibile in uno specifico seed, documentare esattamente il limite.

Il counterfactual seed 0 ha già dimostrato che 21 planted + 21 watered è ottenibile con 4 Hands.

---

# 2. Day-1 workforce

Usa hiring aggressivo immediato.

Baseline prevista:

```text
4 Hands
```

entro l'inizio del Day 1.

Il Farmer resta primariamente responsabile del livestock core.

Gli Hands devono costruire contemporaneamente la massa crop esterna.

Non aspettare:

- core complete;
- Cow #1;
- feed stabilization;
- Day 2;
- Day 10.

La crescita crop deve iniziare nel Day 1.

---

# 3. Divisione funzionale del lavoro

## Farmer

Priorità:

```text
livestock core
livestock logistics
feed
milk

```

## Hands

Priorità:

```text

```

Questa separazione non deve essere assoluta se esiste idle capacity, ma deve impedire che il livestock blocchi la costruzione della massa crop.

---

# 4. Livestock core

Mantieni invariato il core fisico 2×2:

```text
(3,3)
(3,4)
(4,3)
(4,4)
```

o le coordinate effettive già validate se differenti.

Invariant:

```text
nessun core tile può mai diventare crop
```

Il core deve restare riservato al livestock per l'intero episodio.

---

# 5. Cow timing

Non è necessario comprare Cow #1 prima della saturazione crop Q0 se questo rallenta il Day-1 target.

Priorità Day 1:

```text
1. build core pasture
2. hire workforce
3. saturate external Q0 crop
4. irrigate
5. livestock bootstrap appena compatibile
```

La Cow #1 può entrare:

- nel Day 1 se non compromette la saturazione;
- altrimenti immediatamente nel Day 2.

Non ripristinare la serializzazione X1.8.

---

# 6. Target livestock

X1.9 deve avere come target architetturale:

```text
8 active animals
```

non più 4.

Preferenza iniziale:

```text
Cow
```

salvo evidenza meccanica/ROI già presente nel progetto che renda utile una combinazione differente.

Scaling desiderato:

```text
1
→ 2
→ 4
→ 8 animals
```

o equivalente progressivo.

Non acquistare 8 animali in modo cieco.

Ogni step deve rispettare:

```text
feed available
pasture capacity
cash sustainability
worker capacity
```

Ma non usare gate temporali fissi.

---

# 7. Espansione land

X1.8 ha fallito perché Q1/Q2 venivano acquistati troppo tardi o mai.

X1.9 deve acquistare:

```text
Q1
Q2
```

**il prima possibile**, compatibilmente con la sostenibilità economica.

Non aspettare:

```text
Q0 fully optimized
livestock fully complete
8 animals
perfect weed state
```

La logica deve essere:

```text
productive mass
→ revenue
→ land purchase
→ immediate centered activation
```

---

# 8. Land purchase priority

Usa i costi reali del motore.

Non assumere costo fisso.

Per ogni quadrante candidato calcola:

```text
actual land cost
cash after purchase
operational reserve
current productive capacity
```

L'acquisto deve essere aggressivo, non conservativo.

Il principio è:

> Se il capitale consente di comprare nuova terra e mantenere sufficiente workforce/seed/feed per iniziare a svilupparla, l'espansione deve avvenire.

---

# 9. Centered expansion

Quando Q1/Q2 vengono acquistati, NON attivare tile casuali o periferici.

Priorità spaziale:

```text
distance from central livestock/core area
```

La crescita deve partire dai tile più vicini al centro e procedere verso l'esterno.

Target visuale:

```text
central productive mass
→ compact expansion
→ larger centered working set
```

Non:

```text
sparse islands
edge-first expansion
```

---

# 10. Q1/Q2 initial development

Dopo ogni acquisto land:

1. identifica i tile nuovi più vicini al centro;
2. aggiungili al working set;
3. assegna Hands sufficienti;
4. pianta e irriga;
5. amplia progressivamente il raggio.

Non sbloccare un intero quadrante nel working set in una sola volta se la workforce non può mantenerlo.

Distinguere sempre:

```text
owned land
```

da:

```text
active working set
```

---

# 11. Workforce scaling dopo Day 1

Gli Hands devono scalare in funzione dell'obiettivo di crescita, non soltanto del working set già esistente.

Il modello corretto è:

```text
desired productive expansion
→ required workers
→ HIRE
→ productive mass
```

non:

```text
current productive mass
→ workers
```

Mantieni il costo Fibonacci giornaliero sotto controllo, ma considera che i primi Hands sono estremamente economici.

---

# 12. Crop capacity

La precedente regola:

```text
4 crop tiles per Hand
```

non deve impedire la saturazione Day 1 già dimostrata dal counterfactual.

Rivaluta il capacity gate in base alla capacità reale osservata.

Se il replay dimostra che un Hand può mantenere più di 4 tile grazie alla sequenza temporale di crop growth/watering, usa una capacità operativa derivata dalle azioni effettivamente necessarie, non un moltiplicatore statico arbitrario.

---

# 13. Feed strategy

Il feed non deve bloccare la crescita.

È ammesso un bootstrap tramite:

```text
BUY_PRODUCT WHEAT
```

se economicamente piccolo e utile.

Obiettivo successivo:

```text
self-produced Wheat
```

con buffer sufficiente per 8 animali.

La transizione deve essere:

```text
purchased feed bootstrap
→ self-sustaining Wheat loop
```

Non imporre un'attesa di giorni fissi.

---

# 14. Weed control

Weeds nel working set devono essere gestite prima di espandere ulteriormente la superficie attiva.

Ma non usare:

```text
weed_count > 0
```

come gate assoluto alla land expansion.

Il criterio deve essere operativo:

```text
current workforce can recover/maintain existing working set
```
