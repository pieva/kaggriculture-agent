## Approved design direction

Implement the approved X1.11 architecture with these constraints.

### 1. New strategy mode

Add and route:

```text
E12_Q0Q1_80K_ENGINE_X111
```

inside the existing ProductiveMassROIAgent architecture.

Do not replace previous modes.

### 2. Q0 + Q1 only

Disable any Q2 acquisition path for X1.11.

The strategy must stop land expansion once:

```text
owned_quadrants == 2
```

No hidden or fallback Q2 purchase is allowed.

### 3. Early livestock pipeline

Treat early livestock as an economic engine, not a late add-on.

Use the verified engine pipeline:

```text
BUY_ANIMAL
→ FEED
→ 8-day warmup
→ HARVEST Milk
→ worker inventory
→ DROP at shed
→ shed inventory
→ SELL
→ reinvest
```

Important verified mechanics:

- Milk collection uses `HARVEST`, not `COLLECT`.
- Cow `first_yield_day = 8`.
- Workers must operate using their own position.
- Product gathered into worker inventory must reach the shed before market sale.

Fix the known livestock dispatch bug where Hand logic compares against:

```text
state.farmer_position
```

instead of the Hand's actual `(hx, hy)`.

The design should support early cows around Day 2–6, but do not hardcode 4+4 merely because it was proposed.

Use an economic gate for:

```text
4 → 8 cows
```

based on:

- post-purchase cash;
- feed sufficiency;
- functioning Milk pipeline;
- worker capacity;
- remaining episode horizon;
- expected payback;
- crop opportunity cost.

### 4. Dynamic Wheat/feed sizing

Do NOT hardcode exactly 4 Wheat tiles.

Derive feed capacity from:

- active cows;
- feed frequency;
- Wheat consumption;
- remaining horizon;
- current Wheat inventory;
- crop yield;
- opportunity cost of using tiles for Wheat.

Use the minimum internal Wheat surface that reliably supports profitable livestock.

`BUY_PRODUCT Wheat` must NOT be an automatic refill.

Retail Wheat is permitted only as an emergency action when preserving an otherwise profitable livestock cycle has positive EV.

Every retail Wheat purchase must be visible in telemetry.

### 5. Harvest velocity first

X1.10 showed that high physical utilization is not enough.

Prioritize:

```text
mature crop HARVEST
ready Milk HARVEST
```

above low-value maintenance when appropriate.

Minimize:

```text
maturity → harvest
```

waiting time.

A mature crop left waiting is immobilized capital.

### 6. Dynamic crop economics

Do not select crops from nominal unit price or gross yield alone.

Use a phased selector informed by expected:

```text
realized revenue
- seed cost
- labor burden
- water burden
- opportunity cost
- market-price effect
```

with attention to:

```text
net contribution / tile-day
time-to-cash
```

Phases may include bootstrap, growth, and endgame, but the crop mix must be economically motivated.

Avoid blind Tomato/Strawberry saturation.

### 7. Worker architecture and logistics

Use actor-correct state throughout.

Tasks should distinguish farmer vs Hands and use each actor's own position.

Operational priorities should approximately favor:

1. ready livestock harvest / critical feed;
2. mature crop harvest;
3. high-ROI replant;
4. economically necessary watering;
5. logistics / return-to-shed;
6. secondary maintenance.

Do not force all livestock logistics through the farmer if Hands can execute them.

Implement the full shed logistics path:

```text
worker carrying Milk/crops
→ move to shed
→ DROP
→ centralized inventory
→ SELL
```

Prevent valuable inventory from remaining stranded on workers.

### 8. Selling policy

Monetization must be intentional, not residual.

Track and manage:

- sell cadence;
- current cash;
- reserve;
- inventory;
- reinvestment need;
- feed reserve;
- product market price.

Do not assume that selling all Milk immediately is optimal.

However, do not withhold inventory merely to satisfy a price heuristic if final-money EV is worse.
